# UMBRA SHIFT

*Turn the world. Shift the shade.*

A perspective puzzler made for **[GitHub Game Off 2026](https://itch.io/jam/game-off-2026)**. The theme is **SHIFT**.

You are a small lantern-spirit in a tiny stone world. You can't jump. You can only walk left and right and **turn the world 90°**:

- **Walls become floors.** Gravity always pulls toward the bottom of your screen, so every turn changes what is up.
- **Shadows become platforms.** A lamp always hangs on the right of your screen. Obsidian stones cast shadows toward the screen's left, and *shadows are solid*. Turn the world and the light turns with it, so every shadow shifts into a new bridge, wall or ledge.
- **You block the lamp too.** Your own shadow is not solid, so where you stand changes which shadows exist.
- **Void crystals shatter you.** Don't worry: the fatal move is rewound automatically.

There are 12 handcrafted levels. Each has a par move count, and most hide an optional spark.

## Controls

| Action | Keys |
| --- | --- |
| Walk | `A` / `D` or `←` / `→` |
| Turn the world | `Q` / `E` |
| Undo | `Z` (or `Backspace`) |
| Restart level | `R` |
| Music on/off | `M` |
| Menu | `Esc` |

You can also play with the mouse or touch, using the on-screen buttons.

## How it was made

- **Engine:** Unity 6 (6000.4.3f1), built-in render pipeline. The whole project was driven from the Unity command line.
- **No imported assets.** Every mesh is a Unity primitive. All materials are generated by an editor script. All sound effects and the ambient music are synthesized in code at startup (`Synth.cs`).
- **Verified puzzles.** The rules live in a pure C# class (`Sim.cs`). A breadth-first solver checks that every level is solvable and confirms its par before each build. Level candidates were generated and searched by a solver, then curated by hand.

```
Assets/
  Resources/levels.txt      all 12 levels, plain text (# wall, C obsidian, X void, G exit, * spark, S start)
  Scripts/Sim.cs            the rules + BFS solver
  Scripts/Game.cs           rendering, animation, input, UI
  Scripts/Synth.cs          procedural audio
  Editor/Pipeline.cs        CLI entry points: Setup, Validate, BuildWebGL, BuildWindows
Tools/sim.py, gen.py        Python twin of the rules + the level generator used for design
```

### Build from the command line

```bash
UNITY="C:/Program Files/Unity/Hub/Editor/6000.4.3f1/Editor/Unity.exe"
"$UNITY" -batchmode -quit -projectPath . -executeMethod Pipeline.Setup        # materials, scene, player settings
"$UNITY" -batchmode -quit -projectPath . -executeMethod Pipeline.Validate     # solve every level, check par
"$UNITY" -batchmode -quit -projectPath . -executeMethod Pipeline.BuildWebGL   # -> Builds/WebGL
"$UNITY" -batchmode -quit -projectPath . -executeMethod Pipeline.BuildWindows # -> Builds/Windows
```

Running the Windows build with `-autoshot` plays a scripted demo and saves screenshots to `Builds/Windows/shots/`.

### Making levels

Edit `Assets/Resources/levels.txt`. Each level is written as `= Title`, then `; hint`, then `! par`, then the grid. Run `Pipeline.Validate`. It fails if a level can't be solved or if its par doesn't match the shortest solution.
